# SealMail 毕业论文主线整理

本文用于统一毕业论文的业务主线、技术主线和实现主线。核心结论可以概括为一句话：

> 以组织边界邮件安全为目标，基于 Postfix 和国密传输代理构建邮件传输边界，在 SealMail 后端中编排 TLS/TLCP、S/MIME、SPF/DKIM/DMARC 与 DLP 等能力，将邮件安全事实转化为投递、加密、隔离、阻断和审计等业务动作。

## 1. 研究起点

邮件仍然是组织内部和跨组织正式通信的基础通道，承载合同传递、审批流转、系统通知、安全通报和材料交换等业务。邮件的安全风险也很明确，主要包括：

- 相邻节点之间的传输链路可能被监听或篡改。
- 邮件正文和附件可能在中继、落盘或转发过程中泄露。
- 发件身份和域名来源可能被伪造。
- 敏感信息可能被误发到外部域。
- 安全处置结果可能无法追踪和复盘。

在国密场景下，系统还需要兼容 SM2、SM3、SM4、国密证书体系以及国密 TLS/TLCP。

## 2. 为什么采用网关方案

PKI、证书、私钥和 S/MIME 的用户侧学习成本较高。若要求用户改造客户端、统一使用某一个客户端，或者让每个用户直接承担完整的证书管理和加解密流程，落地成本会明显上升，推广也容易受阻。

网关方案把复杂性集中到组织边界：

- 用户仍按原有方式收发邮件。
- 证书、策略、审计和隔离由网关统一处理。
- 安全能力在后端透明执行，尽量不打断用户习惯。

因此，论文的研究对象适合定义为“基于 Postfix、国密传输代理和 SealMail 后端协同的组织边界邮件安全网关”。

## 3. 为什么使用成熟 MTA

完整邮件网关需要处理 SMTP 接入、队列、重试、退信、回注、并发、幂等和协议兼容等一整套 MTA 语义。直接裸写一个完整网关，工程复杂度和维护成本都很高。

更合理的结构是：

- Postfix 负责标准 SMTP 接入、队列和回注。
- 国密传输代理负责国密 TLS 或 TLCP 的传输边界。
- SealMail 后端负责内容安全、策略决策、隔离审计和管理 API。

这种划分复用了成熟 MTA 能力，也把公网暴露面收敛到了可控范围。

## 4. 四类主干能力

从网关可观察的邮件对象和处理结果看，主干能力可以整理为四类。它们与四类安全问题存在主责对应关系。

| 能力 | 主要解决的问题 | 典型观察点 | 系统角色 |
| --- | --- | --- | --- |
| TLS / TLCP / 国密 TLS | 传输保密 | SMTP 会话、`Received` 头中的逐跳记录 | 传输边界 |
| S/MIME | 内容保护 | MIME 结构、签名块、加密载荷 | 内容保护 |
| SPF / DKIM / DMARC | 来源认证 | `DKIM-Signature`、`Authentication-Results`、DNS 策略结果 | 身份判断 |
| DLP | 敏感内容识别与处置 | 命中事件、隔离记录、审计记录 | 决策层 |

其中前三类机制主要生成安全事实，DLP 将这些事实与邮件内容、方向、域名策略和证书能力结合起来，输出最终动作。

### 4.1 原始邮件中可观察到的痕迹

如果从收件方能看到的 SMTP RAW 或原始邮件对象看，通常能够观察到三类痕迹：

- S/MIME：在 MIME 结构中最直接，可看到签名或加密封装。
- DKIM：邮件头中可直接看到 `DKIM-Signature`。
- SPF / DMARC：通常通过接收方写入的 `Authentication-Results` 观察。
- TLS：一般只能通过 `Received` 头中的逐跳信息间接判断。

如果网关对 S/MIME 邮件执行自动解密，最终投递的明文载荷里可能不再保留 S/MIME 外壳。此时应通过处理记录、审计记录和状态信息保留“该邮件曾经过 S/MIME 保护并被网关处理”的事实。

## 5. 系统结构主线

系统结构可以进一步压缩为三层：

1. **公网边界层**
   - Postfix 承担标准 SMTP 接入和队列语义。
   - 国密传输代理承担国密伙伴域的传输边界。

2. **内容安全层**
   - SealMail 后端负责路由、邮件认证、S/MIME、DLP、隔离和回注。
   - 消息管道以 DSL 方式编排处理顺序，形成稳定的入站、出站和释放流程。

3. **管理与审计层**
   - 管理 API 负责证书、域名、DLP、邮件认证、国密传输代理和权限配置。
   - 处理记录、隔离记录、DLP 事件和审计日志用于复盘处置结果。

当前实现中，邮件处理的核心链路已经形成统一的状态和记录模型，前端仪表盘和管理 API 也围绕这条主线展开。

## 6. 论文叙事顺序

建议全文按下面的顺序展开：

1. 业务需求与问题提出。
2. 邮件安全机制映射：TLS/TLCP、S/MIME、SPF/DKIM/DMARC、DLP。
3. 网关总体架构：Postfix、国密传输代理、SealMail 后端。
4. 关键模块实现：路由、认证、S/MIME、DLP、隔离、回注、审计。
5. 双云服务器与真实邮件验证。

这样的顺序能够形成从业务风险到协议机制、再到架构承载和实现验证的完整主线。

## 7. 可直接复用的总述

可用于论文摘要、绪论或章节开头的一段表述如下：

> 本文围绕组织边界邮件安全网关展开研究。系统以 Postfix 负责标准 SMTP 边界和队列语义，以国密传输代理负责国密 TLS/TLCP 传输接入，以 SealMail 后端负责内容安全、策略决策、隔离审计和管理配置。围绕 SMTP 邮件生命周期，系统将 TLS/TLCP、S/MIME、SPF/DKIM/DMARC 和 DLP 等机制统一纳入同一处理链，分别解决传输保密、内容保护、来源认证和敏感信息处置问题，并最终转化为投递、加密、隔离、阻断和审计等业务动作。
